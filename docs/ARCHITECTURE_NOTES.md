## 2. Client startup and connection

**Load.** RED4ext loads `red4ext/plugins/zzzCyberpunkMP/CyberpunkMP.dll` (the `zzz`
prefix makes it load after Codeware/ArchiveXL/TweakXL). `code/client/Main.cpp`:

```cpp
case RED4ext::EMainReason::Load:
    App::GApplication = MakeUnique<App::Application>(aHandle, aSdk);
    App::GApplication->Bootstrap();
    const auto scriptPath = GCyberpunkMpLocation / TP_REDSCRIPT_LOCATION; // "assets/redscript"
    aSdk->scripts->Add(aHandle, scriptLocation);          // redscript compiles these
    ArchiveXL::RegisterArchives(...); TweakXL::RegisterTweaks(...);
    ...
    for (auto& mod : Settings::Get().mods)               // --mod=<folder> launch flag
    {   aSdk->scripts->Add(aHandle, mod...); ArchiveXL::RegisterArchives(mod); ... }
```

- The scripts are registered with redscript by the plugin, so if the DLL fails during
  `Load`, none of CyberpunkMP's `.reds` compile and the game starts as if no mod were
  installed. First diagnostic: `<game>/red4ext/logs/red4ext-*.log`.
- `--mod=<folder>` is an official hook for extra scripts/archives/tweaks. We do not use it
  yet (we install to `r6/scripts/ChoomCoop/`, see TESTING.md) but it is the cleanest way
  to ship ChoomCoop as a CyberpunkMP add-on later.

**Launch flags** (`code/client/App/Settings.cpp`): `--online` enables the mod,
`--ip=<addr>`, `--port=<n>` (default 127.0.0.1:11778), `--mod=<path>`, `--rpc` and
`--rpcdir=<path>` (RPC stub generation, §4). Use the `=` form; the Night City fork
reports that `--ip 1.2.3.4` (space) silently keeps the default.

**Connect.** `NetworkService` (C++) connects over GameNetworkingSockets and sends
`AuthenticationRequest` (protocol identifiers + username). The server
(`code/server/native/GameServer.cpp`, `HandleAuthentication`) checks the identifiers, then
sends **`RpcDefinitions` first and `AuthenticationResponse` second**, then creates the
player. On success the client calls the scripted `NetworkWorldSystem.OnConnected()`
(`code/assets/redscript/World/NetworkWorldSystem.reds`), which sets the blackboard flag
`UIGameData.UIMultiplayerConnectedToServer`. ChoomCoop hooks this with `@wrapMethod`.

Client log: spdlog file next to the DLL (`CyberpunkMP.log`,
`code/client/Support/Spdlog/SpdlogProvider.cpp`).

## 3. Server startup and plugin lifecycle

1. `Server.Loader.exe` (`code/server/loader/Program.cs`) calls
   `CyberpunkMp.ServerAPI.Initialize()` (native), registers update/join/leave callbacks,
   then `Run()`.
2. On the first update the static constructor of `Server.Loader.Server` runs
   (`code/server/loader/Server.cs`): it creates `World`, `RpcManager`, `PlayerSystem`,
   `Timer`, publishes them on `CyberpunkSdk.Server.*`, **then** loads plugins, then the
   WebApi.
3. **Discovery** (`code/server/loader/Systems/Plugins.cs`): for each folder
   `plugins/<Name>/`, load `<Name>.dll`, find type `<Name>.Plugin`, run its static
   constructor, and let `RpcManager.ParseAssembly` register every method tagged
   `[ServerRpc]` / `[ClientRpc]`. `<Name>` must end in `System` (the loader strips that
   suffix for the display name, and the xmake plugin scan only picks `*System` folders).
   A static `Instance` property implementing `IWebApiHook` adds an admin web API; an
   `assets/` folder adds admin widget files.
4. **Events** available to plugins (`code/server/scripting/CyberpunkSdk`):
   - `Server.PlayerSystem.PlayerJoinEvent / PlayerLeftEvent` (`ulong id`)
   - `Server.World.UpdateEvent` (`float delta`, every server tick)
   - `Server.Timer`, `Server.PlayerSystem.GetById(id)` -> `Player` (`Username`,
     `PuppetId`, `MovementComponent`, `SendChat`)
   - `new Logger("Name")` -> console + `logs/Name.log`
5. Release builds refuse to start the WebApi unless `CYBERPUNKMP_ADMIN_USERNAME` and
   `CYBERPUNKMP_ADMIN_PASSWORD` are set (`code/server/loader/Systems/WebApi.cs`). Any
   values work for local testing.

Minimal plugin (ours, `Mods/ChoomCoop/Server/ChoomCoop.Server/Plugin.cs`):

```csharp
namespace ChoomCoopSystem {
public class Plugin {
    public static Plugin Instance { get; }
    static Plugin() { Instance = new Plugin(); }
    private Plugin() {
        Log.Info($"[ChoomCoop:Core] Server plugin loaded v{ModInfo.Version}");
        Server.PlayerSystem.PlayerJoinEvent += OnPlayerJoin;
        Server.PlayerSystem.PlayerLeftEvent += OnPlayerLeft;
    }
}}
```

Verified headless on 2026-10-18: the server prints
`[Plugin:ChoomCoop] [ChoomCoop:Core] Server plugin loaded v0.0.1` and
`[Plugin:SDK] Loaded Plugin: ChoomCoopSystem`.

**Templates to copy:** `EmoteSystem` (one client->server RPC + one server->client RPC +
admin widget, ~60 lines) is the best minimal template. `JobSystem` shows
multi-file RPC classes, per-player state, timers and struct arguments.

## 4. The RPC system

Redscript defines the contract; C++ wires it at script-compile time; C# stubs are generated.

**Client -> server.** A redscript class that **directly** extends `CyberpunkMP.ServerRpc`,
declared `native`, with `static native` functions:

```swift
public native class EmoteServer extends ServerRpc {
    public static native func TriggerEmote(name: String) -> Void;
}
```

`code/client/App/Network/Rpc/RpcValidator.cpp` hooks the redscript validator; for each
such class it registers a native RTTI class and generates a JIT thunk per function
(`RpcGenerator::CreateFunction`, xbyak). Calling `EmoteServer.TriggerEmote("wave")`
serializes the arguments and sends `client::RpcCall{id, bytes}`.

**Server -> client.** A non-native redscript class extending `CyberpunkMP.ClientRpc` with
ordinary methods. The client receives `server::RpcCall`, looks the handler up and calls
the method **with a null instance** (`RpcService::Call`, `CallFunctionWithStack(nullptr, ...)`):
these methods must never use `this`.

**Allowed argument types** (`RpcValidator.cpp`): Bool, Int32/Uint32, Int64/Uint64, Float,
Double, String, CName, TweakDBID, arrays of these, and script structs/classes composed of
them. No handles (`ref<>`, `wref<>`), no `out`/`opt` params.

**Server side.** Plugins contain generated C#:

```csharp
// Server/Plugins.EmoteServer.cs (generated)
[ServerRpc(Class = 16273172002596938280, Function = 8330132648100619273)]
public static void TriggerEmote(ulong playerId, IBuffer data) {
    var name = data.ReadString();
    TriggerEmote_Impl(playerId, name);
}
public static partial void TriggerEmote_Impl(ulong playerId, string name); // you write this

// Client/Plugins.EmoteClient.cs (generated): call EmoteClient.TriggerEmote(playerId, ...)
```

**Code generation.** The official way is to launch the game with
`--online --rpc --rpcdir="<folder>"` (xmake target `RpcGenerator`, `code/loader/xmake.lua`):
the client compiles all redscript, writes `Server/*.cs`, `Client/*.cs`, `RedTypes.cs`, and
exits. Namespace = `Cyberpunk.Rpc.Server|Client` + the module name minus its first segment
(module `ChoomCoop.Protocol` -> `Cyberpunk.Rpc.Server.Protocol`).

**We found the ids are plain FNV-1a 64 hashes**, so stubs can be written and checked
without the game (verified against EmoteSystem's generated values, see
`Mods/ChoomCoop/Server/ChoomCoop.Server.Tests/RpcIdTests.cs`):

| id | hashed string | example |
|---|---|---|
| class | module-qualified class name | `CyberpunkMP.Plugins.EmoteServer` |
| server function | function short name | `TriggerEmote` |
| client function | redscript mangled name `Name;ArgTypes` | `TriggerEmote;Uint64String` |

ChoomCoop keeps hand-written stubs in the generator's exact shape, with the ids in
`Mods/ChoomCoop/Shared/Protocol/RpcIds.cs`. The Phase 0 test includes one `--rpc` run to
confirm our hand-written stubs match what the generator emits.

**Defining a new RPC (checklist):** add the function to `Shared/Protocol/Protocol.reds`;
add its name + id to `RpcIds.cs`; add the stub under `Rpc/Server` or `Rpc/Client`;
implement `_Impl`; add a test row; document it in `docs/PROTOCOL.md`; bump
`ProtocolVersion` if an existing signature changed.

## 5. Remote players: spawn and sync

- Each client sends its position at the server's `update_rate`
  (`NetworkWorldSystem::UpdatePlayerLocation`, flecs system).
- The server (flecs ECS, `code/server/native/Game/Level.cpp`) buckets entities into grid
  cells of `60 * 100` units (`sCellSize`) and streams entities within `sCellLoadRadius = 3`
  cells to each player (`NotifyCharacterLoad` / `NotifyEntityUnload` / `NotifyEntityMove`).
  **Two players far apart do not see each other**; a teleport causes a load/unload burst.
- Spawning: the client calls the scripted `NetworkWorldSystem.CreatePuppet` which uses
  Codeware's `DynamicEntitySystem.CreateEntity` with records `Character.MaMuppet` /
  `Character.WaMuppet` (a "muppet" is an NPC body driven by the network), tagged
  `CyberpunkMP.Puppet`.
- Appearance: the character-creator state (`CharacterCustomizationState`) is serialized
  and applied to the muppet; equipment through `AppearanceSystem` / `AttachmentComponent`
  (`code/client/App/World/AppearanceSystem.cpp`, `code/assets/redscript/World/AppearanceSystem.reds`).
- Movement/animation: `InterpolationSystem` smooths transforms;
  `code/client/Game/Animation/*` drives idle/walk/sprint states. Emotes use workspots
  (`workspot_base.workspot`).

## 6. Vehicles and passengers

- `EnterVehicleRequest{id, position, rotation, vehicle_id, sit_id, remote_vehicle_id}` /
  `ExitVehicleRequest` (`code/protocol/client.proto`); server replies with
  `NotifyVehicleLoad`, `NotifyVehicleControlAssigned`, `NotifyVehicleEnter/Exit`.
- The driver owns the vehicle; passengers are attached to seats
  (`code/client/App/World/VehicleSystem.cpp`, `code/assets/redscript/World/VehicleSystem.reds`,
  `@wrapMethod(PlayerPuppet)` hooks on mount/unmount).

## 7. Build notes (how it actually builds today)

A clean checkout no longer builds with the README steps. Fixes found in Phase 0, all
without editing upstream C++:

1. **xmake 2.9.9**, not 3.x and not 2.9.6 (2.9.6 maps MSVC 14.44 to a non-existent `v144`
   toolset).
2. **Pin the xmake package repo** to the state of 2024-12-21: today's `xmake-repo` pulls
   abseil 2026 which conflicts with gamenetworkingsockets. `xmake-requires.lock` exists but
   is stale (no mimalloc 2.1.7) and its policy is off. We add a local repo clone at
   commit `704a10506` with `xmake repo --add --global` (local repos are never auto-pulled
   and take priority).
3. **Windows SDK < 10.0.26100** for the project (`--vs_sdkver=10.0.18362.0` here).
4. **CppSharp 1.1.84** for SdkGenerator (the pinned 1.1.5 bundles a Clang older than 19,
   which MSVC 14.44's STL rejects: `STL1000`). This is a 2-line upstream csproj change.
   SdkGenerator swallows exceptions and exits 0, so the visible error is later:
   `namespace 'Internal' does not exist`.
5. **pnpm 9** for the admin widgets (pnpm 10+ blocks package build scripts).
6. A current **7-Zip** on PATH (xmake's bundled 7z 19.00 lacks `-snl-`).

Exact commands are in `CLAUDE.md` -> Build.

## 8. Engine APIs for Choom Co-op

Confidence: **high** = signature in CDPR scripts/Codeware source and already used by
upstream or a published mod; **medium** = signature confirmed, behaviour for our use not
proven; **low** = plausible, needs an in-game probe. Probes are in `docs/TESTING.md`
-> "Phase 0 research probes".

### 8.1 Teleport + wait for streaming — high (teleport) / medium (streaming wait)

```swift
// core/systems/teleportationFacility.script
GameInstance.GetTeleportationFacility(game).Teleport(player, position, EulerAngles(0,0,yaw));
```

Used by many mods (e.g. djkovrik/CP77Mods `WannabeEdgerunner/helpers/TeleportHelper.reds`).
There is no public "streaming finished" event in scripts. Best available signals:
- `NavigationSystem.IsNavmeshStreamedInLocation(pos, tolerance)` (core/systems/navigationSystem.script)
  -> poll every 0.25 s after teleport; navmesh streams with the sector, so true means
  the ground is there.
- Ground check: a downward raycast via Codeware's physics helpers
  (`vendor/Codeware/scripts/Physics/`) or `NavigationSystem.IsOnGround(owner)`.
Plan: fade out, teleport, poll until both pass or 10 s timeout, then fade in; on timeout
fall back to the nearest fast-travel point (PLAN.md §3.5). Probe P1.

### 8.2 Safe navmesh-snapped position near a player — high (API) / medium (results)

```swift
let res = GameInstance.GetNavigationSystem(game)
    .FindPointInSphereOnlyHumanNavmesh(targetPos, 3.0, NavGenAgentSize.Human, false);
if Equals(res.status, worldNavigationRequestStatus.OK) { /* use res.point */ }
```

(`NavigationFindPointResult{status, point}`, core/systems/navigationSystem.script.) The
target client computes this (navmesh exists only where streamed). Probe P2.

### 8.3 Saving — medium

- **Block saves:** `ScriptableSystem` has a virtual `IsSavingLocked() -> Bool`
  (core/systems/scriptableSystem.script); `BraindanceSystem`, `PreventionSystem`,
  `SceneSystem` and `TakeOverControlSystem` override it to block saving. Our
  `ChoomCoopSystem` can override it and return `true` while in Guest Mode. Alternative:
  `SaveLocksManager.RequestSaveLockAdd(game, n"ChoomCoopGuest")`. The pause menu checks
  `GameInstance.IsSavingLocked(game, locks)` (cyberpunk/UI/fullscreen/ingame/pauseMenu.script).
  **Unproven for autosave and quicksave**; Probe P3. Belt-and-braces for Phase 2: also
  `@wrapMethod` the quicksave/save request paths.
- **Detect load:** `ScriptableSystem.OnRestored(saveVersion, gameVersion)` runs after a
  save is loaded; `OnAttach` on every session start.
- **Save folder:** `%USERPROFILE%\Saved Games\CD Projekt Red\Cyberpunk 2077\` (one folder
  per save: `sav.dat`, `metadata.9.json`, `screenshot.png`). Same for Steam/GOG/Epic.
  Snapshots must happen outside the game (native or launcher), since redscript cannot copy
  files. Codeware has no general file API; this is the one place we may need C++ (Phase 2).

### 8.4 Quest / journal / facts (Host) — high

```swift
// core/systems/questSystem.script
let qs = GameInstance.GetQuestsSystem(game);
qs.GetFact(n"some_fact"); qs.RegisterListener(n"some_fact", this, n"OnFactChanged");
// core/systems/journalManager.script
GameInstance.GetJournalManager(game)
    .RegisterScriptCallback(this, n"OnJournalEntryStateChanged", gameJournalListenerType.State);
protected cb func OnJournalEntryStateChanged(entryHash: Uint32, className: CName,
    notifyOption: JournalNotifyOption, changeType: JournalChangeType)
```

(used verbatim by cyberpunk/devices/UI/internet/browserController.script). Facts need
known names (from WolvenKit); journal callbacks give every quest/objective change.

### 8.5 Scene / restricted control detection — high

PSM blackboard `PlayerStateMachine.SceneTier` / `HighLevel` with `gamePSMHighLevel`
values `SceneTier1..SceneTier5`. The player already listens to it:
`PlayerPuppet.OnSceneTierChange` (cyberpunk/player/player.script:1103) -> we can
`@wrapMethod` it. Tier >= 3 = limited/cinematic control (same threshold the game uses to
block time skip, cyberpunk/activityCardsManager/activityCardsHelper.script:22). Also
useful: `PlayerStateMachine.Combat == gamePSMCombat.InCombat`, `.Vehicle`,
`IsInLoreAnimationScene`. Probe P4 prints the values during a scene.

### 8.6 XP, street cred, money, items — high (items) / medium (XP)

- **XP & street cred:** `PlayerDevelopmentData.AddExperience(amount, type: gamedataProficiencyType, reason, isDebug)`
  (cyberpunk/systems/playerDevelopmentSystem.script:659); street cred is
  `gamedataProficiencyType.StreetCred`, level is `.Level`. `@wrapMethod` it to record
  (amount, type). UI listens to `ProficiencyProgressEvent`.
- **Items & money:** `TransactionSystem.RegisterInventoryListener(player, callback)` with a
  subclass of `InventoryScriptCallback` overriding `OnItemAdded`, `OnItemRemoved`,
  `OnItemQuantityChanged` (core/components/inventoryComponent.script). Money is the item
  `Items.money` (`OnItemQuantityChanged` with its diff). Pattern used by
  core/systems/craftingSystem.script:39.

### 8.7 Custom map pins / world markers — high

```swift
let data: MappinData; data.mappinType = t"Mappins.QuestStaticMappinDefinition";
data.variant = gamedataMappinVariant.DefaultQuestVariant; data.visibleThroughWalls = true;
let id = GameInstance.GetMappinSystem(game).RegisterMappinWithObject(data, puppet, n"poi_mappin", Vector3(0,0,2));
// or RegisterMappin(data, position), SetMappinActive, UnregisterMappin
```

(core/systems/mappinSystem.script; upstream uses it in `code/assets/CET/init.lua` and
`code/assets/redscript/Plugins/Mappins.reds`, plus custom minimap widgets in
`code/assets/Archives`.) Attaching to the remote player's muppet gives a moving pin.

### 8.8 Spawn an NPC and disable its AI (puppet) — high (spawn) / medium (AI off)

Spawn exactly like upstream's player muppets (Codeware `DynamicEntitySystem`, see §5).
Disable AI: `AIHumanComponent.SetCurrentRole(npc, new AINoRole())` (used by
core/gameplay/effectors/quickhackEffectors.script:453) plus `AIComponent.SetAIRole`; or
spawn a record without AI like `Character.MaMuppet`. Muppets are the proven path; real
NPC records keep combat AI unless suppressed. Probe P5.

### 8.9 Damage an NPC from script; detect death — medium

- Damage/kill: `StatPoolsSystem.RequestSettingStatPoolValue(npc.GetEntityID(), gamedataStatPoolType.Health, value, instigator)`
  (core/systems/statPoolsSystem.script:51). Setting Health to 0 kills through the normal
  death pipeline. Proper hits (with hit reactions) need `AttackData`, later.
- Death: `protected cb func OnDeath(evt: ref<gameDeathEvent>)` on the NPC (core/components/aiComponent.script:273),
  or watch the Health stat pool. Probe P6.

### 8.10 HUD element, notification, radial menu — high (HUD/notification) / low (radial)

- **HUD:** upstream already ships custom ink widgets via ArchiveXL (`multiplayer_ui.inkwidget`,
  `code/assets/redscript/Ink/*.reds`). Codeware's `inkCustomController` lets us build
  widgets in code without new .inkwidget files.
- **Notification:** the UI_Notifications blackboard `OnscreenMessage` (Variant of
  `SimpleScreenMessage`) shows the yellow on-screen message (core/blackboard/blackboardDefinitions.script:1572).
  Probe P7.
- **Radial menu:** the game's radial menus (`radialHubMenuGameController.script`, emote
  selector) are hard-wired. Upstream already has a custom selector:
  `code/assets/redscript/Ink/EmoteSelector.reds` -> best template. Low confidence until
  we try; a simple list menu is the fallback.

## 9. Open risks found in Phase 0

1. **Game version.** Upstream targets 2.2. On a current game (2.31+) it reportedly does
   not start. Options: (a) rebase onto `ofmiceandcam98-eng/CyberpunkMP` (2.31, same
   license); (b) downgrade the game to 2.2 (Steam depot downloader; GOG offers old
   installers). Wyatt to decide.
2. Hand-written RPC stubs rely on the mangled-name hash rule; verified against one example.
   The `--rpc` run in the Phase 0 test confirms it.
3. Redscript cannot be compile-checked on this machine (no game install here), so the first
   compile happens in Wyatt's game. A single bad `.reds` file disables every script.
